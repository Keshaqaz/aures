# Третья площадка воркера: Cloudflare Workers

**Отклонено** живой пробой 26 октября 2026 года: `chatgpt.com/backend-api` отвечает на запросы из Workers страницей 403 от Cloudflare, без JSON. Это касается `wham/usage`, списка сбросов и consume. Вход через `auth.openai.com` и refresh при этом работают. Без `chatgpt.com` воркер не может ни читать квоты, ни применять сбросы. Ниже — решение в том виде, в каком его проверяла проба.

26 октября 2026 года владелец решил добавить Cloudflare Workers третьей площадкой, равноправной с GitHub и Google Apps Script. Шаги пользователя должны быть автоматизированы так же полно, как на других площадках. Раньше Cloudflare уже был в проекте, но только как **таймер**: он запускал workflow GitHub (ADR-0002, ADR-0003). Теперь он **исполнитель**: воркер целиком живёт в аккаунте Cloudflare пользователя. Решение примет живая проба `.scratch/cloudflare-worker/issues/01-deploy-probe.md`. До неё ADR остаётся `proposed`.

**Решение.**
- Воркер — модуль Workers в аккаунте пользователя. Его тот же `tick`, что на GitHub и Google, вызывает Cron Trigger `*/5 * * * *`. Окно правила перед истечением — 1 ч, как на Apps Script.
- State, общие правила, журнал и флаг расписания хранит один Durable Object на SQLite-хранилище: на плане Free доступно только оно. Шифрования нет по той же причине, что на Apps Script: ключ лежал бы в том же аккаунте.
- Durable Object однопоточен, но во время исходящего `fetch` в него входят другие запросы. Поэтому тик и изменяющие действия идут под явным мьютексом внутри объекта. Это аналог `LockService`.
- Связь CLI с воркером — `fetch` на `https://aures-worker.<subdomain>.workers.dev` по тому же протоколу действий, что `doPost` на Apps Script (`status`, `trial`, `wake`, `apply_now`, `login`, `rules`, `schedule`, `revoke`, `uninstall`), с секретом из Keychain. У воркера секрет хранится как Worker secret. Повседневные команды не требуют входа в Cloudflare.
- Пауза снимает флаг расписания в Durable Object, а Cron Trigger остаётся. Тик на паузе ничего не делает. Так паузе и переключению не нужен токен Cloudflare. Проба проверяет, не надёжнее ли снимать сам Cron Trigger через API.
- Вход CLI в Cloudflare — OAuth Device Authorization Grant (RFC 8628) с **публичным client_id Wrangler**: `https://dash.cloudflare.com/oauth2/device/auth`, затем `/oauth2/token`. Пользователь видит код и нажимает «Allow», копировать ничего не нужно. Этот приём уже используется для ChatGPT с client_id Codex. Scope минимальные, точный набор определяет проба (кандидаты: `account:read`, `user:read`, `workers_scripts:write`, `offline_access`). Refresh token хранится в Keychain, токен нужен только для деплоя: `setup`, `upgrade`, «Починить», переключения и `uninstall`.
- Всё остальное CLI делает сам через API Cloudflare, без Wrangler: выбирает аккаунт (если их несколько, спрашивает), заводит subdomain `workers.dev`, если его нет, загружает модуль с привязкой Durable Object, миграцией `new_sqlite_classes` и секретом, включает `workers.dev` и ставит Cron Trigger.
- `uninstall` удаляет скрипт вместе с Durable Object и отзывает OAuth-токен Cloudflare. Ручных шагов, как на Google, не остаётся. Аккаунт Cloudflare и subdomain `workers.dev` принадлежат пользователю, CLI их не трогает.

**Пересматривает ADR-0004, раздел «Отвергнуто»** («Cloudflare и любой внешний таймер — лишний аккаунт»). Противоречие: у пользователя появляется аккаунт Cloudflare. Причина пересмотра: аккаунт нужен только тем, кто сам выбрал эту площадку. GitHub остаётся вариантом без нового аккаунта, а ADR-0007 уже сделал площадки выбором пользователя. Сохраняется: своего сервера нет, код воркера у каждого пользователя свой, reusable action и общий центральный воркер по-прежнему отвергнуты.

**Уточняет ADR-0007.** Площадок три. Правило «активный воркер не больше одного», порядок переключения (новый готовится → старый гасится → у нового включается расписание), отказ при применении с неизвестным исходом и перенос только общих правил применяются ко всем парам площадок. Переключение предлагает выбрать одну из двух других площадок. ADR-0002 и ADR-0003 остаются заменёнными: таймер для GitHub не возвращается.

**Отвергнуто.**
- API-токен по предзаполненному шаблону. Это официальный путь, но пользователь копирует токен, а у токена есть срок и ротация. Остаётся запасным вариантом, если проба покажет, что device flow Wrangler недоступен сторонней программе.
- Деплой через `wrangler`. Это лишняя зависимость в сотни мегабайт, а API загрузки модуля покрывает всё нужное.
- KV для state. Он eventually consistent, а `pending` и применение требуют строгой последовательности. Free даёт 1 000 записей в сутки.
- Таймер Cloudflare для воркера GitHub (ADR-0002). Это два аккаунта вместо одного, а пунктуальность и так даёт воркер на самом Cloudflare.

**Последствия и риски (их проверяет проба).**
- `chatgpt.com` и `auth.openai.com` сами стоят за Cloudflare. Запросы из Workers могут получить challenge или 403. Если это так, площадка неработоспособна и решение отклоняется.
- CPU 10 мс на вызов на Free. Ожидание сети в него не входит, но разбор JSON и миграции state входят.
- Device flow Wrangler показывает пользователю название «Wrangler», а не aures. Cloudflare может ограничить использование client_id сторонними программами, тогда нужен переход на шаблон API-токена.
- Cron Triggers: 5 на аккаунт. Изменения триггеров распространяются до 15 минут.
- Новый subdomain `workers.dev` начинает отвечать не сразу. Задержку измеряет проба, а `setup` её ждёт, как `askAfterDeploy` на Google.
- О потере сессии воркера Cloudflare писем не шлёт. Её показывают `status` и экран; Mac на этой площадке тоже будит воркер (ADR-0005).
